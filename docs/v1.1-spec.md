## Glossary

- **Holding** — a row in `holdings[]` (one ticker + shares + cost + cached prices)
- **Refresh** — N parallel Yahoo fetches (one per holding) that update `current_price`, `high_52w`, `low_52w`, `prev_close` for all holdings
- **Market state** — derived from chart endpoint's `currentTradingPeriod` + `gmtoffset` (chart endpoint doesn't return `marketState` directly)
- **Intraday** — any time when a market is active (pre, regular, post sessions, including extended)
- **Per-record merge** — ADR 0004 newer-wins-by-`updated_at` rule; handles new fields transparently

**Load-time** (per Q16). Idempotent. Bump happens before any save trigger.

## 2. Yahoo client (`lib/yahoo.js`)

New file. Pure functions, browser-compatible (IIFE pattern like `lib/format.js`).

### 2.1 Public API

```js
// Module-exports + window.Yahoo for browser
{
  fetchQuotes(symbols, fetchFn = window.fetch),  // returns Promise<Records>
  YahooAuthError, YahooNetworkError, YahooParseError,  // error classes
}
```

`bootstrapAuth` and crumb handling were removed when Yahoo locked the quote endpoint — see [research/05](../research/05-chart-endpoint.md). The chart endpoint needs only cookie+UA, handled by the Worker.

### 2.2 `fetchQuotes(symbols, fetchFn)`

**Input**: `symbols: string[]` — e.g. `['AAPL', '2330.TW', 'TWD=X']`
**Output**: `Promise<Record<string, QuoteResult>>` — keyed by symbol.

```ts
type QuoteResult = {
  current_price: number | null,
  high_52w: number | null,
  low_52w: number | null,
  prev_close: number | null,
  marketState: 'PRE' | 'REGULAR' | 'POST' | 'CLOSED',
  currency: string | null,
  regularMarketTime: number | null,
} | {
  failed: true,            // symbol not found, parse error, or network error
}
```

### 2.3 Implementation contract

1. **Per-symbol fetch** (parallel via `Promise.all`): GET `https://query1.finance.yahoo.com/v8/finance/chart/<SYMBOL>?interval=1d&range=1d`. When `PORTFOLIO_CONFIG.yahooProxyUrl` is set, the URL is rewritten to `${proxy}/?url=<encoded>`.
2. **Parse response**: `response.chart.result[0].meta` is the meta object. Map fields per §2.5. If `result` is null/empty, mark symbol as `failed: true`.
3. **No retry**: chart endpoint is stable; transient failures mark the symbol as failed and surface to the UI. The retry loop in `portfolio.html` (5× with backoff) handles refresh-level retry at a higher layer.
4. **Derive marketState** from `meta.currentTradingPeriod.{pre,regular,post}` + `meta.gmtoffset` + current time. FX (`meta.instrumentType === 'CURRENCY'`) always returns `'CLOSED'`.

### 2.4 Throws

- `YahooAuthError` — bad input (no fetchFn, symbols not array)

Per-symbol failures (404 = not found, 500/429 = server/rate, parse error) are NOT exceptions — they are `{ failed: true }` entries. The UI marks the row with a red badge and surfaces a "Retry failed N" button.

### 2.5 Field mapping (chart endpoint → QuoteResult)

| QuoteResult field | Yahoo chart field |
|---|---|
| `current_price` | `meta.regularMarketPrice` |
| `high_52w` | `meta.fiftyTwoWeekHigh` |
| `low_52w` | `meta.fiftyTwoWeekLow` |
| `prev_close` | `meta.chartPreviousClose` |
| `marketState` | derived (see §2.3) |
| `currency` | `meta.currency` |
| `regularMarketTime` | `meta.regularMarketTime` |

### 2.5 DI for testability

`fetchQuotes(symbols, fetchFn)` accepts a fetch function. Default `window.fetch`. Tests pass a mock that returns canned Yahoo responses.

### 2.6 CORS caveat

`query1.finance.yahoo.com` does not send CORS-permitting headers for arbitrary origin. This is a known limitation of the unofficial API. **Implementation will likely need a fetch proxy** (e.g., a CORS-anywhere mirror) OR a paid plan. **This is a known open problem** — see §11 Open questions.

## 3. Refresh mechanism

### 3.1 Manual button

- **Placement**: Global `<header>`, between sync and currency toggle (Q9-Q10: high frequency group).
- **Label default**: "↻ Refresh"
- **Click**: triggers `refreshAllPrices()` action described below.

### 3.2 `refreshAllPrices()` algorithm

```
function refreshAllPrices() {
  state = 'refreshing'
  symbols = mapped(holdings, h => h.ticker)
  failures = []

  for attempt in 1..5 (auto-retry):
    results = await fetchQuotes(symbols)
    failed = symbols.filter(s => results[s]?.failed)
    if failed.empty: break
    failures = failed
    symbols = failed  // retry only the failed
    if user_clicked_button_again: break  // cancel signal

  // Apply successful results, even if some failed
  for h in holdings:
    r = results[h.ticker]
    if r && !r.failed:
      h.current_price = r.current_price
      h.high_52w = r.high_52w
      h.low_52w = r.low_52w
      h.prev_close = r.prev_close
      h._refresh_failed = false
    else:
      h._refresh_failed = true

  state = 'idle' (or 'partial' if any failures)
  await save()
}
```

### 3.3 Auto-retry details

- **Attempts**: 5 (per Q7)
- **Spacing**: 1s, 2s, 4s, 8s, 16s exponential backoff (so total max wait ~30s)
- **Cancel**: any user click on the refresh button during retry breaks the loop. In-flight fetch is not abortable (browsers don't easily abort fetch), but no further attempts run. State returns to idle with current results applied.
- **Per-symbol retry**: only the failed symbols are re-queried on subsequent attempts. This means Yahoo's batch endpoint is still used with reduced `symbols` list.

### 3.4 Partial success

- **Successful holdings**: updated as normal.
- **Failed holdings**: marked `_refresh_failed = true`, kept old cached values. UI shows red badge on the row.
- **After retry exhaustion**: red badge persists. Conditional "Retry N failed" button appears.
- **Red badge clear**: automatically cleared on next successful refresh (of that holding). Does NOT require manual intervention.

### 3.5 Total failure

If `fetchQuotes` throws `YahooAuthError` / `YahooNetworkError` (not a per-symbol failure):
- All holdings keep their old values.
- Header shows error banner: "Refresh failed: <reason>."
- No retry button (issue is at the request level, not per-symbol).

### 3.6 State transitions

```
       click
idle ─────────► refreshing
  ▲                │
  │   no failures  │     partial failures
  │                ▼
  └─── ◄── idle   ──► partial
                      │  click again
                      ▼
                    retrying (auto-retry)
                      │
                      ▼
                  partial (or idle if all succeed)
```

Button label by state:

| State | Label | Style |
|---|---|---|
| `idle` | "↻ Refresh" | Default |
| `refreshing` | "Refreshing..." | Disabled, spinner |
| `partial` | "↻ Refresh" + "🔄 Retry N failed" | Default + secondary button |
| `error` | "↻ Refresh" + error banner | Default + banner |

### 3.7 What is NOT included

- **No auto-refresh on timer** — manual button only (per Q2). v1.2 might add periodic refresh.
- **No polling** — `fetchQuotes` is one-shot per click.
- **No per-row refresh button** — bulk only (per Q2).

## 4. UI — Holdings table

### 4.1 New columns

| Column | Source | Format | Mobile |
|---|---|---|---|
| (existing) Symbol | `ticker` | text | Yes |
| (existing) Shares | `shares` | `formatAmount()` | Yes |
| (existing) Cost | `cost` | `formatAmount()` | Yes |
| (existing) Current price | `current_price` | `formatAmount()` | Yes |
| **NEW: Day Δ%** | computed | `±X.XX%`, color | Yes |
| **NEW: 52W range bar** | computed | visual bar | Below price on mobile |

### 4.2 Day Δ% computation

```js
dayDeltaPercent(h) = h.prev_close == null
  ? null  // → show "—"
  : ((h.current_price - h.prev_close) / h.prev_close) * 100
```

**Display**:
- `+1.23%` — green
- `-1.23%` — red
- `0.00%` — neutral (gray)
- `—` — gray (when prev_close is null)

**Format**: 2 decimals, sign explicit, `%` suffix. No compact suffix (always 2 decimals).

### 4.3 52W range bar

Visual bar showing where current price sits between 52W low and high.

```
Day Δ%   52W Range
+1.23%   ▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌📍
         ├─────────────●────────────┤
         low $180              high $240
         current $215
```

**Computation**:
```js
position = h.high_52w == null || h.low_52w == null
  ? null
  : (h.current_price - h.low_52w) / (h.high_52w - h.low_52w)
  // clamp to [0, 1] in case current is outside [low, high]
```

**Display**:
- Horizontal bar, ~120px wide on desktop
- Marker dot at `position × width`
- Colors: gray track, blue/accent marker
- **Out-of-range**: if current > high or < low, marker pegs at edge
- `—` placeholder text when high or low is null

**Layout proposal** (TBD during UI mockup):
- Desktop: bar inline with current price (right side of row)
- Mobile: bar below price, narrower (~80px)

### 4.4 Lazy populate placeholder

When `high_52w`, `low_52w`, or `prev_close` is `null`:
- Display `—` (em dash) in the relevant column
- Tooltip / hint: "Refresh prices to populate" (shown on first encounter only?)

### 4.5 Red badge (refresh failure)

When `_refresh_failed === true`:
- Row gets a red border-left or background tint
- Tooltip: "Last refresh failed for this holding"
- Clears automatically on next successful refresh

### 4.6 Alerts / toasts

- After refresh (idle → idle): toast "Prices updated ✓" (auto-dismiss 2s)
- After partial refresh: toast "Prices updated. N failed." (manual dismiss)
- After total failure: error banner at top of header

## 6. Snapshot interaction

### 6.1 Snapshot schema

Unchanged. Only `current_price` per holding (per Q13, Q14).

### 6.2 Intraday confirm dialog

**Trigger**: User clicks "Snapshot" action.

**Logic**:
```js
function shouldWarnIntraday() {
  for (h of holdings) {
    if (h.currency === 'FX') continue;  // FX exception
    const meta = lastQuoteResults[h.ticker];
    if (meta && INTRADAY_STATES.has(meta.marketState)) return true;
  }
  return false;
}

const INTRADAY_STATES = new Set(['PREPRE', 'PRE', 'REGULAR', 'POST', 'POSTPOST']);
```

**If intraday**: show confirm dialog:
- Title: "現在盤中，價格會波動，要繼續嗎？"
- Body: "Snapshot 會記錄當下的 current_price，之後可能與收盤價不同。"
- Buttons: [取消] [繼續]

**If all closed** (or no data): no dialog, snapshot proceeds immediately.

**Closing behavior**: snapshot saved regardless of choice (per Q15). The dialog is purely informational, not a gate.

### 6.3 Missing data

If `lastQuoteResults` is `null` (refresh has never run), no warning. Defensive default: "no signal" → no warning.

### 6.4 FX exception

`quoteType === 'CURRENCY'` (e.g. `TWD=X`) is excluded from intraday detection. FX doesn't have a meaningful intraday concept. Hard-skip via holding's `currency === 'FX'` filter.

## 7. Error paths

### 7.1 Total Yahoo failure (HTTP 401, 5xx, network)

- Header shows error banner: "Refresh failed: <reason>."
- No holdings updated.
- User can click button to retry from scratch.
- No auto-retry at this level (per-symbol auto-retry only fires when Yahoo returns symbols but some are missing).

### 7.2 Partial failures

- Successful holdings updated.
- Failed holdings: red badge, old values kept.
- Auto-retry 5x as per §3.3.
- After exhaustion: "Retry N failed" button visible.

### 7.3 Rate limiting (HTTP 429)

- Detected via `response.status === 429`.
- Treat same as total failure (§7.1).
- Possibly add longer backoff (e.g. 60s) before allowing manual retry. (Implementation detail; not blocking.)

### 7.4 Auth (crumb) expiry

- 401 response on quote fetch → re-bootstrap once (cookie + crumb), then retry the quote call.
- If second attempt also 401 → `YahooAuthError`, surface as total failure (§7.1).

### 7.5 User cancellations

- User clicks refresh button during retry → cancel signal honored at next loop iteration.
- In-flight fetch continues (no abort), but results from it are still applied if successful.
- After cancel: state returns to idle with whatever updates succeeded so far.

### 7.6 Form manual override

- Form fields remain editable.
- Refresh overwrites manual values (per Q5).
- No warning before overwrite (user triggered refresh, expected outcome).
- If user wants to keep manual values, they shouldn't click refresh.

## 8. Migration & version

**Source: [§3-§4 of schema-section.md](schema-section.md#3-migration-rule-v10--v11).** Recap:

### 8.1 On load

1. Read file (localStorage or Drive).
2. If `version !== '1.1'`, run migration:
   - Shallow-merge `defaultPortfolio()` to ensure all v1.1 fields exist.
   - For each holding, set `high_52w`, `low_52w`, `prev_close` to `null` if missing.
3. Set `version: '1.1'` immediately. Don't wait for save.

### 8.2 Non-destructive

- No existing values are touched.
- No user confirmation needed.
- UI shows `—` for new fields until first refresh.

### 8.3 Backward compatibility

- v1.0 app loading v1.1 file: ignores extra fields. Edits in v1.0 silently drop new fields.
- v1.1 app loading v1.0 file: handled by migration.
- Cross-device sync: both sides must be v1.1 to round-trip new fields.

### 8.4 Persistence

- Save to localStorage on every refresh (after applying results).
- Sync to Drive if auto-sync enabled (existing behavior).

Use `node:test` (no new deps). Mock `fetchFn` — pass canned Yahoo responses.

**Test scenarios**:

| Scenario | Mock setup | Expected |
|---|---|---|
| Single symbol, full response | `fetchFn` returns valid `/v7/finance/quote` JSON for one symbol | Parsed `{ ticker, current_price, ..., marketState }` |

### 9.2 Retry state machine tests

Unit test the `refreshAllPrices` retry logic with a mock `fetchQuotes`:

| Scenario | Mock behavior | Expected |
|---|---|---|
| All succeed on first try | Returns complete results | 1 attempt, no retries |
| Some fail, second try succeeds | First call returns 2 failures; second call returns those 2 | 2 attempts, all updated |
| All 5 attempts fail | Always returns same failures | 5 attempts, then surfacing "Retry N failed" |
| User cancels after 2 attempts | User click simulated after attempt 2 | State back to idle, partial results applied |
| Mixed success/failure across attempts | Pattern: 2 fail, retry, 1 fail, retry, 0 fail | 3 attempts, all updated |

## 11. Open questions

These are **not blocking** for spec sign-off. Implementation tickets may need to decide.

### 11.1 CORS for Yahoo API

`query1.finance.yahoo.com` does not send CORS headers for arbitrary origin. Options:
- **(a) CORS proxy** — use a public proxy (cors-anywhere, allorigins, etc.) — fragile, dependency on third party
- **(b) Self-hosted tiny proxy** — deploy a minimal Cloudflare Worker / Vercel function that proxies Yahoo. Costs $0 on free tier. Adds backend (violates ADR 0008 constraint of "no backend")
- **(c) Browser extension** — CORS disabled in extension context
- **(d) Wait for change** — Yahoo may eventually add CORS (unlikely)

**Recommendation**: document the limitation; defer implementation choice until user can install a proxy. Until then, refresh is documented as "may not work in all browsers due to CORS."

### 11.2 52W range bar visual design

Spec describes the math but not the visual. Implementation should:
- Mock up 2-3 alternatives
- Pick one
- Document choice in implementation commit

Open options: bar with markers (current proposal), gradient fill, sparkline.

### 11.3 Mobile breakpoint specifics

Spec says "mobile collapses low-frequency items to menu". Exact breakpoint (600px? 768px?) deferred to implementation.

### 11.4 Refresh button — text vs icon-only

Spec suggests icon-only on mobile. Implementation can decide.

### 11.5 Crumb refresh cadence

How often does Yahoo's crumb expire? Empirically check during implementation. If short-lived (e.g. 1 hour), refetch every refresh. If long-lived (days), cache across sessions.

### 11.6 `lastQuoteResults` storage

The spec needs `marketState` for snapshot intraday detection. Should this be:
- (a) Cached in-memory only (lost on reload, requires explicit refresh to detect intraday)
- (b) Persisted to localStorage with timestamp

**Recommendation**: (a) — simpler, no schema change. Snapshot intraday warning is best-effort.
