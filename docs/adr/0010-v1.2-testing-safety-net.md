# 0010 — v1.2 testing safety net: required checks, browser smoke, Worker contract tests, lib/ extraction

## Status

Accepted (v1.2)

## Context

The v1.1 release shipped three regressions that all surfaced only when the user clicked "refresh" in the browser and watched the failure happen:

1. **Script-tag omission** — `lib/yahoo.js` was added in v1.1 implementation but the `<script>` tag in `portfolio.html` was not updated, so the page loaded without the new module. The page rendered; refresh did nothing.
2. **Caller-contract mismatch** — the inline `refreshAllPrices` was refactored but the call site passed the wrong shape to `Yahoo.fetchQuotes`, so the retry loop saw 0 results and reported "all failed".
3. **Yahoo endpoint drift** — Yahoo locked `/v7/finance/quote` behind browser-session-derived crumb auth in 2025; the worker silently started returning 401 with no schema-level test to catch it. The fix / research to switch to `/v8/finance/chart/<SYMBOL>` is documented in [`research/05-chart-endpoint.md`](../research/05-chart-endpoint.md) and [ADR 0009 §11](0009-v1.1-price-tracking.md).

The existing `./test.sh` covers `lib/` modules (96%+ line coverage) but is blind to the inline Alpine code in `portfolio.html` (~1284 lines), the Cloudflare Worker runtime, and the wiring between `portfolio.html` ↔ `lib/` ↔ `docs/workers/yahoo-proxy.js` ↔ Yahoo.

v1.2 introduces a **safety net** that catches the recent regression class at commit time. The underlying refactor (extract pure logic from `portfolio.html` into `lib/`) is the same shape as the v1 spec's `lib/` extraction; the new piece is the committed gate that keeps regressions from sneaking back in.

## Decision

### 1. Split into required checks and a live canary

**Required checks** run on every agent commit, fail fast, and block development. They cover the deterministic surfaces: Node unit tests on `lib/`, Worker contract tests mocking `globalThis.fetch`, a Wrangler dry-run bundle check, and a Playwright browser smoke against a local dev server with mocked Yahoo responses. None of these touch the real internet.

**Live canary** is a separate, optional `./scripts/canary.sh` (out of scope for ticket 01, deferred to a post-v1.2 ticket) that hits the deployed Worker URL with a real Yahoo symbol and asserts the response shape. It runs before release, not on every commit. Failures are reported but never block ordinary development.

**Rejected**: a single end-to-end check that talks to real Yahoo. Reasons: meaningful flakes (5xx from Yahoo, transient network) become commit-gate flakes; the user would `git commit --no-verify` to make progress, and the gate would lose its meaning.

**Rejected**: only required checks, no canary. Reasons: the canary is what catches the "endpoint drift" regression class (Yahoo moved us from `/v7/finance/quote` to `/v8/finance/chart/<SYMBOL>` mid-v1.1). Without it, the next endpoint lockout ships silently.

**Rejected**: only canary, no required checks. Reasons: the canary is too slow and too flaky to gate commits; the recent regression class (script tag omitted, caller shape wrong) is deterministic and caught cheaply by Node tests + browser smoke.

### 2. Playwright for browser smoke (Chromium only)

**Playwright is the browser smoke runner.** Rationale: zero-dep browser binaries via `npx playwright install`, mature debugging API (`page.on('console')`, `page.on('pageerror')`, network route mocking), and a single test runner that covers both a unit test and a browser test flavor (`@playwright/test`).

**Rejected**: Cypress. Reasons: separate test runner for browser ≠ same DX as `./test.sh`, larger install footprint, heavier reporter.

**Rejected**: a curl-based smoke against the deployed Worker. Reasons: only catches the Worker-side regression class; misses the script-tag-omission and caller-contract-mismatch classes that live in `portfolio.html` ↔ `lib/` wiring.

**Rejected**: multi-browser matrix (Firefox, WebKit). Reasons: the recent regression class is browser-agnostic (DOM state, fetch wiring). Chromium is sufficient for v1.2. Multi-browser is a follow-up if a browser-specific bug appears.

The smoke mocks at the Worker URL boundary (read from `window.PORTFOLIO_CONFIG.yahooProxyUrl` if set, falling back to a glob like `**/yahoo-proxy*/**`) — not at `query1.finance.yahoo.com`. Mocking at Yahoo's URL would let the same regression class recur: `lib/yahoo.js`'s URL construction, the `fetchFn` default, and the browser `fetch` call must all be exercised.

### 3. Five-module extraction: `lib/calc.js`, `lib/group.js`, `lib/refresh.js`, `lib/sync.js`, `lib/snapshot.js`

The recent regression class lived in **inline Alpine code** in `portfolio.html`. The testable surface (`lib/`) had only `format.js`, `intraday.js`, `market-display.js`, `serialize.js`, `yahoo.js`. The other 90% of the logic — totals, grouping, refresh orchestration, sync merge, snapshot assembly — was untested.

**v1.2 extracts five new `lib/` modules** in the order: calc → group → refresh → sync → snapshot. Each module follows the existing IIFE + CommonJS export pattern (browser + Node `:root` / `module.exports` shim). Each is paired with a `tests/<module>.test.js` and the corresponding Alpine method becomes a thin shim — one call into the module plus reactive bookkeeping.

**Rejected**: keeping logic inline and adding a Playwright test that exercises it. Reasons: tests then have to start a browser, fill a form, and inspect the DOM — slow, brittle, and doesn't tell you which line broke. Extracting to `lib/` lets the same logic be unit-tested in milliseconds with a mock `fetchQuotes`.

**Rejected**: extracting everything at once in a single mega-PR. Reasons: a single ~700-line diff to `portfolio.html` is un-reviewable; the diff per ticket has to be ~50-200 lines so the reviewer can verify behaviour preservation per chunk.

**Rejected**: introducing a new framework (e.g. moving logic to a Vuex store). Reasons: the existing `lib/` convention works; replacing the framework is a multi-quarter effort and out of scope.

### 4. `lib/refresh.js` API contract

The refresh workflow is the highest-value extraction — it's the exact workflow where the recent bugs lived. The API is fixed by this ADR so the extraction ticket (06) compiles against a stable target:

```js
runRefresh({
  symbols,                       // string[] — required
  fetchQuotes,                   // (symbols) => Promise<Record> — required, injected
  maxAttempts = 5,               // number
  backoffMs = n => [1000, 2000, 4000, 8000, 16000][n - 1] ?? 0,
  sleep,                         // (ms) => Promise<void> — required, injected
  isCancelled = () => false,
  isFailed = e => e?.failed === true,
  onAttempt,                     // ({ attempt, maxAttempts, results, succeeded, failed, isFinal }) => void
})
// returns { attempts: number, succeeded: string[], failed: string[], cancelled: boolean }
```

Rules pinned by this contract:

- `succeeded` / `failed` are computed after each attempt and returned in the final result. Symbols missing from the result object count as failed.
- Attempt 1 does not check `isCancelled` at the loop head; an attempt-1 success is never "cancelled". Attempt 2 onwards checks before and after the fetch.
- `isCancelled` is checked again after the per-attempt fetch returns, before sleeping. The in-flight fetch is not aborted (matches [ADR 0009 §2](0009-v1.1-price-tracking.md)).
- `onAttempt` throwing is swallowed; the refresh continues.
- After the final attempt, no sleep.
- The library is unaware of holdings, `_refresh_failed`, or schema flags. The Alpine layer applies the result back onto `data.holdings`.

The caller wires `fetchQuotes: Yahoo.fetchQuotes` and `isCancelled: () => this.refreshCancelRequested`. `retryFailed` becomes a one-line delegation: `return this.refreshAllPrices(this.refreshFailures)`.

### 5. Pre-commit gate: `./scripts/safety-net.sh`

A new executable shell script runs the four required checks in order and exits non-zero on any failure. Stages 2 (worker contract) and 4 (browser smoke) are conditional: the script prints "skipped" and exits 0 if the target files are absent. This wiring lets ticket 01 itself run the script on a clean tree before its dependent tickets have landed.

`AGENTS.md` is updated with the rule: before any commit that touches `lib/`, `portfolio.html`, `docs/workers/`, `docs/adr/`, `AGENTS.md`, or any `tests/*` file, the agent runs `./scripts/safety-net.sh`. Conditional skips are not a license to skip checks — once a stage's tests exist, the stage becomes unconditional and must pass.

The `npx --no-install` guard on stage 4 ensures the agent uses the pinned version from `package-lock.json` rather than re-fetching from npm.

A new `package.json` and `package-lock.json` carry `@playwright/test` as the sole `devDependency` and a `test:browser` script. `node_modules/` is gitignored.

## Deferred / future

- **ADR 0011 — Yahoo endpoint failure handling.** How the app should behave when the live canary observes a new Yahoo endpoint lockout. Deferred until the first canary failure gives us concrete evidence; designing for hypothetical endpoints leads to over-engineering.
- **ADR 0012 — Required-vs-canary boundary details.** The exact exit-code and reporting conventions for the canary script, the schedule it runs on, and the failure-alert path. Deferred until `./scripts/canary.sh` is actually built (post-v1.2).
- **Multi-browser Playwright matrix.** Add Firefox + WebKit only when a browser-specific bug appears.
- **Coverage threshold.** A coverage gate (e.g. "fail if `lib/` drops below 95%") is a follow-up. Current state is 96%+; the threshold is a forcing function, not a current-truth.
- **GitHub Actions / hosted CI.** Out of scope per v1.2 plan. The local pre-commit gate is the discipline; remote CI is a separate decision.

## Consequences

### Positive

- Recent regression class (script-tag omission, caller-contract mismatch, endpoint drift) is caught at commit time by Node tests + Worker contract tests + browser smoke — three independent angles on the same surface.
- `lib/` extraction makes the bulk of the app's logic testable in milliseconds, decoupled from Alpine lifecycle.
- Pre-commit gate is inherited by future agent sessions via `AGENTS.md` — the discipline doesn't depend on the agent remembering.
- Browser smoke catches the wiring regressions (script tag, fixture state) that pure unit tests cannot.

### Negative

- **Three layers to maintain.** Required checks + canary + manual review. Each adds friction; the trade-off is that without them the recent 3-bug pattern recurs.
- **`npx --no-install` brittleness.** If `node_modules/` is missing (e.g. on a fresh clone), stage 4 fails with a clear "npx: command not found" — the conditional skip catches this for ticket 01, but a future ticket could break the skip condition by accident. The "missing: tests/browser/" message is the safety net for that case.
- **Playwright browser bin download.** `npx playwright install chromium` is ticket 03's responsibility, not 01's. A fresh clone that only runs ticket 01's setup doesn't need the browser binaries.
- **Two sources of coverage truth.** `./test.sh` covers `lib/`, browser smoke covers `portfolio.html` ↔ `lib/`. The split is intentional and matches the seam.
- **Conditional skip can mask forgotten stages.** If a future agent removes `tests/worker.contract.test.js` and the script silently skips, the regression class returns. Mitigation: each safety-net stage logs which path it took (ran vs skipped), and the failure mode is loud ("skipped" in yellow, not silent).

### Trade-offs accepted

| Choice | Trade-off |
|---|---|
| Required checks vs live canary split | Two scripts to maintain; one is a fast gate, one is a slow truth |
| Playwright over Cypress | Same runner covers unit + browser; Playwright is a one-time install |
| Five sequential extraction tickets | More PRs, slower to v1.2 end; each PR is reviewable |
| Chromium only | Misses Firefox / WebKit regressions; multi-browser is a follow-up |
| Mock at Worker URL, not Yahoo | Smoke exercises `lib/yahoo.js` URL construction; if Yahoo changes, the smoke needs an update |
| Conditional skip on stages 2 & 4 | Lets ticket 01 run cleanly on a clean tree; future agents must not regress the skip condition |
| `npx --no-install` | Pinned version; fails clearly if `node_modules/` is missing |

## Alternatives considered

- **Single E2E check that hits real Yahoo.** Too flaky for a commit gate; flakes become `git commit --no-verify` and the gate loses meaning. Rejected.
- **Cypress instead of Playwright.** Separate runner; different DX from `./test.sh`. Rejected.
- **Curl-based smoke against deployed Worker.** Catches Worker-side regressions, misses `portfolio.html` ↔ `lib/` wiring. Rejected.
- **Multi-browser matrix in v1.2.** The recent regression class is browser-agnostic; multi-browser is YAGNI. Rejected.
- **Keep logic inline, add Playwright tests against the inline code.** Slow, brittle, doesn't tell you which line broke. Rejected.
- **Extract everything in one mega-PR.** Un-reviewable diff. Rejected.
- **Introduce a new framework (Vuex, Pinia, etc.).** Multi-quarter effort; the existing `lib/` convention works. Rejected.
- **Hosted CI (GitHub Actions).** Out of scope; local pre-commit gate is the discipline. Rejected.
